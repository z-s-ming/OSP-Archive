# 面向局部用户间冲突恢复代价的主动重置方法

> 文档定位：这是当前主动重置方法的主文档。若与 `主动重置论文研究思路_打磨版.md` 存在表述不一致，以本文档为准。

## 1. 核心问题

多人重定向行走（Redirected Walking, RDW）需要在有限真实空间中支持多个用户连续行走。现有系统通常在用户接近边界、障碍物或其他用户时触发 reset，使用户重新定向以避免真实碰撞。对于用户间冲突，传统被动 reset 能处理即时安全风险，但它主要回答“现在是否必须避免碰撞”，并不显式回答“这次处理之后，两名用户能否稳定恢复连续行走”。

本文关注的问题不是泛泛的“减少所有 reset”，也不是寻找更复杂的 reset 朝向，而是一次用户间局部冲突事件被处理之后的恢复质量。具体而言，本文研究：在用户间冲突尚未进入不可恢复的被动 reset 状态前，是否可以通过一次主动 reset 改善该局部冲突的恢复代价分量。

## 2. 研究目标

本文聚焦多人 RDW 中用户间局部冲突的恢复质量。核心目标是建立一个可观测的局部恢复代价描述，并在此基础上设计主动 reset 策略，使系统能在被动安全 reset 发生前利用仍然存在的恢复余量，改善冲突后的恢复结果。

本文的贡献集中在两点：第一，定义用户间局部冲突后的恢复代价分量；第二，提出基于恢复余量的主动 reset 策略，并检验它是否改善这些分量。reset 朝向沿用原系统或简单规则，局部 max-min 动作选择仅作为实现中的代理决策，用于服务恢复代价分量改善目标。

## 3. 采用的方法

本文的方法可以概括为三步。

第一，系统持续观察两名用户是否正在接近，并预测他们在短时间内会不会进入危险距离。

第二，如果两名用户还没有真正进入危险状态，但恢复余量已经变小，说明此时仍有机会提前处理。系统就在这个窗口中触发候选主动 reset。

第三，系统在“不处理、重置用户 i、重置用户 j”三个动作中选择一个更可能改善恢复结果的动作。选择标准不是让某一个用户收益最大，而是尽量避免任一冲突相关用户很快再次 reset。这样做的目标是减少短时间内多次 reset，并让一次冲突处理后最先再次被打断的用户也能连续走得更远。

## 4. 关键名词定义

### 4.1 用户间局部冲突事件

一个用户间局部冲突事件指在连续时间窗口 `[t0, t1]` 内，用户 `i` 和用户 `j` 在真实物理空间中满足接近条件，并且该 pair 可能触发用户间 reset 或影响后续 reset 分布。

该事件至少需要满足两个条件：

- 两名用户处于邻近或潜在碰撞候选关系，例如真实距离低于候选距离阈值，或处于相邻 partition/cell。
- 两名用户的相对运动具有接近趋势，例如 closing speed 大于阈值，或预测最小距离低于当前距离。

只用“距离近”定义冲突是不够的。两名用户距离近但正在分离时，不一定需要干预。本文关注的是具有接近趋势、可能导致后续 reset 的 pair-level 事件。

### 4.2 恢复结果

一次局部冲突事件后的恢复结果定义为：从该冲突事件被处理或自然结束开始，到下一次相关 reset 或相关用户间事件发生之前，系统给两名用户留下的连续行走结果。

恢复结果不是主观评价，而是一组可观测量：

- `N_interrupted`：该事件打断的用户数量。单侧 reset 为 1，双边 reset 为 2。
- `I_bilateral`：双边 reset 指示量。若同一局部事件导致两名用户均发生 user reset，则为 1，否则为 0。
- `D_next_i` 与 `D_next_j`：事件结束后，用户 `i` 和用户 `j` 各自到下一次相关 reset/event 前的连续行走距离。
- `D_next_min = min(D_next_i, D_next_j)`：该局部冲突事件后，任一冲突相关用户再次发生 reset 前的最短连续行走距离。它表示这次冲突处理后，最先被再次打断的相关用户还能连续走多远。
- `D_next_mean = mean(D_next_i, D_next_j)`：pair 中两名用户的平均连续行走距离，仅作为辅助统计量。
- `I_short_event(τ)`：事件级短距离再次 reset 指示量。若 `D_next_min < τ`，即任一冲突相关用户在冲突处理后 `τ` 米内再次 reset，则 `I_short_event(τ)=1`，否则为 0。本文可报告 `τ=1m, 2m, 3m` 下的结果。

### 4.3 局部恢复代价

本文将局部恢复代价定义为分量指标集合，而不是加权求和的单一分数：

```text
Cost(e) = {
    core continuity metrics: I_short_event_τ(e), D_next_min(e),
    guardrail metrics: N_interrupted(e), I_bilateral(e)
}
```

这些分量的方向是明确的：

- `I_short_event_τ` 越小，说明一次冲突处理后，任一相关用户在短距离内再次 reset 的比例越低。
- `D_next_min` 越大，说明一次冲突处理后，最先被再次打断的相关用户也能连续走得更远。
- `N_interrupted` 和 `I_bilateral` 是保护性指标，用于观察主动 reset 是否扩大打断范围或引入更多双边 reset。它们不是本文的主要优化目标。

`I_short_event_τ` 和 `D_next_min` 本质上描述的是同一个问题的两种表达：一次冲突处理后是否形成稳定连续体验。`D_next_min` 是连续距离表达，回答“最先再次 reset 的相关用户还能走多远”；`I_short_event_τ` 是阈值化表达，回答“是否存在任一相关用户很快再次 reset”。二者都以事件为单位，因为主动 reset 的触发和作用对象就是一次局部冲突事件。

`D_next_mean` 不属于核心恢复代价分量。它只用于说明方法是否同时改变 pair 的平均连续行走距离。平均值不能替代 `D_next_min`，因为一次局部冲突可能让一名用户恢复较好，而另一名用户很快再次 reset；只要任一冲突相关用户很快再次 reset，就说明这次冲突处理没有形成稳定连续体验。

### 4.4 低代价恢复与高代价恢复

在上述定义下，低代价恢复不是主观判断，而是满足以下特征的恢复结果：

- `I_short_event_τ = 0`。
- `D_next_min` 较长。
- `N_interrupted` 和 `I_bilateral` 未明显增加。

高代价恢复定义为满足以下任一条件的恢复结果：

- `I_short_event_τ = 1`，即冲突处理后任一冲突相关用户在短距离内再次 reset。
- `D_next_min` 位于低分位或小于阈值 `τ`。
- `N_interrupted` 或 `I_bilateral` 明显增加，说明方法可能用更大打断范围换取局部连续性。

因此，本文中的“高代价”不是抽象形容词，主要指一次冲突处理后没有形成稳定连续体验：任一冲突相关用户很快再次 reset，或最短连续行走距离很短。打断范围和双边 reset 用于判断这种改善是否带来了额外副作用。

## 5. 理论依据：为什么这些分量与用户体验相关

本文不直接声称恢复代价等同于主观体验，但这些分量可以作为用户体验风险的合理代理指标。依据来自三个方面。

第一，RDW 文献长期使用 reset 数量和 reset 间连续行走距离评价算法质量。APF-RDW 等工作报告 reset 数量下降和 average distance between resets 提高，说明 reset 频率和连续行走距离是 RDW 性能评价中的核心量。因此，`I_short_event_τ` 和 `D_next_min` 是对 distance between resets 的事件级局部化定义：它们不评价整场实验平均走了多远，而评价一次用户间局部冲突处理之后，相关用户是否形成了稳定连续行走。

第二，心理学和人机交互中的任务中断研究表明，中断会带来恢复主任务的时间代价，即 resumption lag。Monk 和 Kidd 的研究显示，即使非常短的 interruption 也可能延迟任务恢复；Monk、Trafton 和 Boehm-Davis 进一步表明，中断持续时间和认知需求会影响恢复 suspended goals 的时间。RDW 中的显式 reset 会迫使用户停止当前连续行走控制、重新定向并恢复行走，因此可以被视为一种空间运动任务中的显式中断。由此，短时间内连续 reset 比单次 reset 更可能破坏行走连续性，`I_short_event_τ` 正是用于识别这种局部恢复失败。

第三，VR presence 研究表明，身体运动与虚拟环境中的存在感相关。Slater 等关于 body movement 和 subjective presence 的实验，以及早期 walking technique 对 presence 的研究，都支持自然身体运动和虚拟运动反馈之间的匹配对 VR 体验有意义。RDW 的目标正是尽可能保留连续自然行走。频繁 reset 或短距离连续 reset 会破坏这种连续性，因此 `D_next_min` 和 `I_short_event_τ` 可以作为“局部恢复后行走连续性”的代理指标。

因此，本文优化目标的体验依据可以表述为：若主动 reset 能减少事件级短距离再次 reset，并提高事件后的最短连续行走距离，同时不明显增加总 reset rows、`N_interrupted` 和 `I_bilateral`，那么它降低了局部冲突后的连续性中断风险。这里的结论仍然是代理指标层面的，不等同于已经证明主观沉浸感显著提升；若要证明主观体验，还需要额外用户实验。

## 6. 恢复余量与主动干预窗口

为了决定是否主动干预，本文定义恢复余量：

```text
M(i,j,H) = d_min(i,j,H) - d_safe
```

其中，`d_min(i,j,H)` 是用户 `i` 和 `j` 在预测窗口 `H` 内的最小预测距离，`d_safe = r_i + r_j + b` 是安全距离，`r_i` 和 `r_j` 是用户安全半径，`b` 是安全缓冲。

恢复余量的含义如下：

- `M > 0`：预测窗口内尚未进入安全边界，仍有主动干预余量。
- `M = 0`：预测最小距离刚好到达安全边界。
- `M < 0`：预测窗口内将进入安全边界，风险已经接近被动安全 reset。

主动干预窗口定义为：

```text
0 < M(i,j,H) ≤ θ(i,j)
and ΔM < 0 over recent frames
and closing_speed(i,j) > v_min
```

该定义避免两个极端：过晚触发会退化为预测版被动 reset；过早触发会打断本可自然恢复的局部冲突。

## 7. 本文优化目标

本文的目标不是减少所有 reset，也不是寻找最优 reset 方向。本文的目标是：

> 在主动干预窗口内，从有限动作集合中选择一个动作，使局部冲突事件的预期恢复代价分量得到改善。

动作集合为：

```text
A = {keep, reset_i, reset_j}
```

其中，`keep` 表示不主动干预，继续由原有 RDW 和被动 reset 机制处理；`reset_i` 表示主动重置用户 `i`；`reset_j` 表示主动重置用户 `j`。

目标判据为：

```text
prefer a over keep
if expected I_short_event_τ(a) decreases
or expected D_next_min(a) increases
while N_interrupted(a) and I_bilateral(a) do not obviously increase
```

由于在线完整预测所有恢复代价分量较难，工程实现中可以使用最短预计可连续行走距离作为代理量：

```text
maximize min(R_i(a), R_j(a))
```

其中，`R_i(a)` 和 `R_j(a)` 表示执行动作 `a` 后，两名用户各自预计还能获得的可连续行走距离。该规则的作用是近似改善 `D_next_min`，并降低 `I_short_event_τ` 的发生概率。它是工程实现，不是本文的独立研究贡献。

## 8. 研究问题

RQ1：在被动用户间 reset 机制下，局部用户间冲突事件后是否存在短时间连续 reset 和低连续行走距离现象？

该问题对应的主要观察指标为 `I_short_event_τ` 和 `D_next_min`。如果 baseline 中存在较高比例的事件级短距离再次 reset，或较低的 `D_next_min`，说明“局部冲突后的行走连续性”是一个需要单独讨论的问题，而不是普通 reset count 可以完全解释的问题。`N_interrupted` 和 `I_bilateral` 作为副作用指标同步报告，用于描述这些局部事件是否伴随更大打断范围。

RQ2：基于恢复余量趋势的主动 reset 是否能改善局部冲突后的行走连续性？

该问题对应 Baseline 与 Active Reset 的比较。核心判断是主动 reset 是否降低 `I_short_event_τ`、提高 `D_next_min`，从而减少短时间多次 reset 并延长事件后的最短连续行走距离。`N_interrupted`、`I_bilateral` 和 total reset rows 用作副作用指标，用于确认这种连续性改善不是通过明显增加打断换来的。

RQ3：主动干预窗口的阈值设置是否具有稳定性？

该问题用于避免方法被质疑为任意调参。可比较 conservative、default、aggressive 三组阈值，主要观察 `I_short_event_τ`、`D_next_min` 和 proactive reset count 的变化，并用 total reset rows、`N_interrupted`、`I_bilateral` 检查是否出现额外打断。

## 9. 方法设计

本文方法包含两步。

第一步是局部主动干预判定：

```text
Trigger(i,j) = 1
if 0 < M(i,j,H) ≤ θ(i,j)
and M has decreased in at least k of recent w frames
and closing_speed(i,j) > v_min
```

第二步是主动 reset 动作选择：

```text
choose reset_i or reset_j
by maximizing the worse-side predicted remaining distance
```

同时加入最小收益门槛：

```text
R_selected - R_keep ≥ δ
```

如果不满足该门槛，则拒绝主动 reset，避免主动 reset 变成额外打断。

## 10. 实验设计

实验 A：问题存在性。

目标是证明 baseline 中确实存在局部连续性恢复失败，而不只是普通 reset 数量问题。应报告：

- baseline 下 `I_short_event_τ` 在 `τ=1m/2m/3m` 下的比例。
- baseline 下 `D_next_min` 的均值、中位数和低分位数。
- baseline 下 `D_next_mean`，仅作为对照。
- baseline 下 `N_interrupted` 和 `I_bilateral`，作为副作用和事件类型描述。

实验 B：主动 reset 主效果。

目标是验证 Active Reset 是否改善局部冲突后的行走连续性。应报告：

- `I_short_event_τ` 是否下降。
- `D_next_min` 是否提高。
- total reset rows 是否没有明显增加。
- `N_interrupted` 是否没有明显增加。
- `I_bilateral` 是否没有明显增加。
- `D_next_mean` 是否同步变化，作为辅助解释。

实验 C：触发阈值敏感性。

目标是证明主动干预窗口不是任意调参。可比较：

- conservative：`T_lead=0.20s, θ_max=0.35m, δ=0.25m`
- default：`T_lead=0.30s, θ_max=0.50m, δ=0.20m`
- aggressive：`T_lead=0.45s, θ_max=0.70m, δ=0.15m`

主要观察 `I_short_event_τ` 是否下降、`D_next_min` 是否提高、proactive reset count 是否过高，以及 total reset rows、`N_interrupted`、`I_bilateral` 是否明显上升。

## 11. 预期贡献

本文贡献应表述为：

1. 本文将多人 RDW 中用户间局部冲突后的恢复结果形式化为事件级连续性指标，包括事件级短距离再次 reset 比例和事件后的最短连续行走距离，并将被打断用户数、双边 reset 作为副作用指标报告。

2. 本文提出一种基于恢复余量趋势的主动 reset 判定方法，在 `M>0` 但恢复余量持续下降时触发候选干预，以减少局部冲突后的短时间多次 reset，并提高事件后的最短连续行走距离。

3. 本文通过多用户仿真实验验证该方法是否降低 `I_short_event_τ`、提高 `D_next_min`，并检查 total reset rows、`N_interrupted` 和 `I_bilateral` 是否明显增加，从而分析其在不同用户密度和阈值设置下的适用边界。

## 12. 不应写成的结论

本文不能写成：

- “显著改善沉浸感”，除非补充主观实验。
- “降低总代价”，因为本文不定义加权总代价函数。
- “解决用户间碰撞”，因为本文研究的是局部冲突后的行走连续性恢复。
- “主要降低双边 reset”，因为双边 reset 是副作用观察指标，不是本文的核心优化目标。
- “提出局部 max-min 仲裁算法”，因为 max-min 只是动作选择的工程近似。
- “提出 reset 方向优化方法”，因为 reset 朝向不是本文贡献。
