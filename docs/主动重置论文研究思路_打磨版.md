# 面向局部用户间冲突恢复代价的主动重置方法

## 1. 研究对象

本文研究的对象不是泛泛的“冲突恶化”，而是多人重定向行走中一次用户间局部冲突事件的恢复结果。

一个局部用户间冲突事件定义为：

> 在连续时间窗口 `[t0, t1]` 内，用户 `i` 和用户 `j` 的真实物理状态满足接近条件，并且该 pair 可能触发用户间 reset 或影响后续 reset 分布。

该事件需要满足两个条件：

1. pair 处于邻近或潜在碰撞候选关系，例如处于相邻 partition/cell，或真实距离低于候选距离阈值。
2. pair 的相对运动具有接近趋势，例如 closing speed 大于阈值，或预测最小距离低于当前距离。

只用“距离近”定义冲突是不够的。两个用户距离近但正在分离，不一定需要干预。本文关注的是“接近趋势可能导致后续 reset”的 pair-level 事件。

## 2. 恢复结果

本文将一次局部用户间冲突事件后的恢复结果定义为：

> 从该冲突事件被处理或自然结束开始，到下一次相关 reset 或相关用户间事件发生之前，系统给用户留下的连续行走结果。

恢复结果不是主观体验评价，而是一组可观测量。本文使用以下变量描述恢复结果：

- `N_reset_user`：该局部事件引发的用户相关 reset 数量。
- `N_interrupted`：被该局部事件打断的用户数量。单侧 reset 为 1，双边 reset 为 2。
- `D_next_i` 与 `D_next_j`：事件结束后，用户 `i` 和用户 `j` 各自到下一次相关 reset/event 前的连续行走距离。
- `D_next_min = min(D_next_i, D_next_j)`：该局部冲突窗口中恢复结果较差一侧用户的连续行走距离。
- `D_next_mean = mean(D_next_i, D_next_j)`：该局部冲突窗口中两名用户的平均连续行走距离，作为辅助指标。
- `I_short_min(τ)`：最差侧短距离恢复指示函数。若 `D_next_min < τ`，则 `I_short_min(τ)=1`，否则为 0。本文可取 `τ=1m, 2m, 3m`。
- `I_bilateral`：双边 reset 指示函数。若同一局部事件导致两名用户均发生 user reset，则为 1，否则为 0。

其中，`D_next_min` 和 `I_short_min(τ)` 是恢复连续性的主要代理指标；`D_next_mean` 用于说明全局平均连续行走是否同步改善，但不作为本文的核心效果指标。这样定义的原因是：一次用户间局部冲突可能让一名用户恢复良好，而另一名用户很快再次 reset；若只报告平均距离，较差一侧的恢复失败会被掩盖。`N_interrupted` 和 `I_bilateral` 是打断范围的主要代理指标。

## 3. 恢复代价

为避免“高代价”成为模糊表述，本文将局部恢复代价定义为一组可观测分量指标，而不是加权求和后的单一分数。

对一次局部用户间冲突事件 `e`，其恢复代价由以下分量描述：

```text
Cost(e) = {
    N_interrupted(e),
    I_bilateral(e),
    I_short_min_τ(e),
    D_next_min(e)
}
```

其中：

- `N_interrupted(e)` 衡量该事件打断了多少用户。
- `I_bilateral(e)` 衡量该事件是否导致 pair 中两名用户均被 reset。
- `I_short_min_τ(e)` 衡量该事件后较差一侧用户是否出现短距离恢复。
- `D_next_min(e)` 衡量该事件后较差一侧用户到下一次相关 reset/event 之前的连续行走距离。

`D_next_mean(e)` 不作为核心恢复代价分量，而是辅助统计量。它用于说明方法是否同时改变 pair 的平均连续行走距离，但不能替代 `D_next_min(e)`，因为平均值可能掩盖较差一侧用户很快再次 reset 的情况。

这些分量的方向是明确的：

- `N_interrupted` 越小，说明打断范围越小。
- `I_bilateral` 越小，说明双边 reset 越少。
- `I_short_min_τ` 越小，说明较差一侧用户的短距离连续 reset 越少。
- `D_next_min` 越大，说明局部冲突中恢复最差用户的连续行走距离越长。

因此，本文不引入 `α, β, γ` 等权重，也不把不同量纲的指标合成为一个总代价分数。论文主文应分别报告这些分量，并用分量是否改善来判断主动 reset 是否降低局部恢复代价。

本文后续实验必须围绕这些分量闭环，而不是只报告某一个派生统计量。具体对应关系为：`N_interrupted` 和 `I_bilateral` 回答“主动 reset 是否扩大打断范围”；`I_short_min_τ` 回答“较差一侧用户是否仍在短距离内再次 reset”；`D_next_min` 回答“局部冲突中恢复最差用户还能连续走多远”。因此，`D_next_min` 不是额外指标，而是恢复代价中“恢复连续性”这一分量的主要度量。`D_next_mean` 只用于补充说明平均连续行走距离是否同步变化。

该指标设计的理论依据有三点。第一，RDW 研究通常使用 reset 数量和 reset 间连续行走距离评价重定向质量，例如 APF-RDW 工作报告了 reset 数量下降和 average distance between resets 提高；因此 `D_next_min` 和 `D_next_mean` 是对 distance between resets 的局部化定义。第二，多用户 RDW 研究已经将用户间碰撞预防、forced stopping 和 user re-orientation 视为对虚拟体验流程的 interruption，并按受影响用户统计 disruption；因此一次 pair-level 冲突若打断两名用户，应比只打断一名用户具有更高恢复代价。第三，心理学和人机交互中的中断研究表明，即使短暂中断也会带来 resumption lag；在 VR 中，显式 reset 会迫使用户停止当前行走控制并重新定向，因此短距离内再次 reset 可以被视为恢复连续性较差的事件。基于这些依据，本文关注的是局部冲突后的 worst-case recovery，而不是所有用户 `D_next` 的平均提升。

## 4. 低代价恢复与高代价恢复

在上述定义下，低代价恢复不是主观判断，而是满足以下特征的恢复结果：

- 只打断一名用户，或没有触发用户 reset。
- `D_next_min` 较长。
- `I_short_min_τ=0`。
- 未出现双边 user reset。

高代价恢复定义为满足以下任一条件的恢复结果：

- `N_interrupted = 2`，即一次 pair-level 冲突打断两名用户。
- `I_short_min_τ = 1`，即冲突后较差一侧用户在短距离内再次 reset。
- `D_next_min` 位于低分位或小于阈值 `τ`。

因此，“高代价”在本文中等价于：

> 更多用户被打断，或冲突后较差一侧用户的连续行走距离不足。

该定义与 RDW 文献中常用的 reset count 和 distance between resets 一致，但评价单位从全局 episode 收缩到局部用户间冲突事件。

## 5. 冲突状态与恢复余量

为了决定是否主动干预，需要定义冲突事件在当前时刻是否仍有恢复余量。

设用户 `i` 和 `j` 在预测窗口 `H` 内的最小预测距离为：

```text
d_min(i,j,H)
```

设安全距离为：

```text
d_safe = r_i + r_j + b
```

其中 `r_i` 和 `r_j` 是用户安全半径，`b` 是安全缓冲。

恢复余量定义为：

```text
M(i,j,H) = d_min(i,j,H) - d_safe
```

解释：

- `M > 0`：预测窗口内仍未进入安全边界，pair 仍有恢复余量。
- `M = 0`：预测最小距离刚好达到安全边界。
- `M < 0`：预测窗口内将进入安全边界，说明被动安全风险已经较高。

因此，本文不应把主动 reset 触发在 `M < 0` 之后。若 `M < 0` 才触发，该方法更接近预测版被动 reset，而不是利用恢复余量的主动干预。

## 6. 主动干预窗口

本文的主动干预窗口定义为：

```text
0 < M(i,j,H) ≤ θ(i,j)
and ΔM < 0 over recent frames
and closing_speed(i,j) > v_min
```

其中：

```text
θ(i,j) = clamp(closing_speed(i,j) · T_lead + b_uncertain,
               θ_min,
               θ_max)
```

推荐初始值：

```text
T_lead = 0.30s
b_uncertain = 0.05m
θ_min = 0.15m
θ_max = 0.50m
```

含义：

- 当前仍有恢复余量，即 `M > 0`。
- 余量已经进入保守阈值区间，即 `M ≤ θ`。
- 余量正在下降，即最近若干帧内 `M` 持续减小。
- pair 仍在接近，而不是自然分离。

这一定义避免了两个极端：

- 过晚触发：等到 `M < 0` 才处理，已经接近被动安全 reset。
- 过早触发：只要预测有风险就 reset，容易打断本可自然恢复的冲突。

## 7. 优化目标

本文的优化目标不是“减少所有 reset”，也不是“找到最优 reset 方向”。本文的目标是：

> 在主动干预窗口内，从有限动作集合中选择一个动作，使局部冲突事件的预期恢复代价分量得到改善。

动作集合为：

```text
A = {keep, reset_i, reset_j}
```

其中：

- `keep` 表示不主动干预，继续由现有 RDW 和被动 reset 机制处理。
- `reset_i` 表示主动重置用户 `i`。
- `reset_j` 表示主动重置用户 `j`。

目标判据为：

```text
prefer a over keep
if expected N_interrupted(a) does not increase
and expected I_bilateral(a) does not increase
and at least one of {I_short_min_τ(a), D_next_min(a)} improves
```

在实际实现中，完整预测所有恢复代价分量可能较难。因此本文可使用可计算代理量来近似动作选择：

```text
maximize  min(R_i(a), R_j(a))
```

其中 `R_i(a)` 和 `R_j(a)` 表示执行动作 `a` 后，pair 中两个用户各自预计还能获得的可连续行走距离。该代理量服务于分量指标改善目标：如果某个动作能提高较差一侧的预计可连续行走距离，则它更可能降低 `I_short_min_τ`，并提高 `D_next_min`。

需要明确的是，局部 max-min 只是工程实现中的动作选择近似，不是本文的独立研究问题，也不应作为论文贡献单独表述。论文主张的是恢复代价定义，以及基于恢复余量的主动 reset 策略。

## 8. 为什么不是方向优化

reset 方向优化回答的是：

> 已经决定 reset 后，朝哪里 reset 更好？

本文回答的是：

> 是否应在被动 reset 前主动干预，以及应该 reset 哪一名用户？

这两个问题不同。若同时引入新的方向优化，实验收益将混合来自三个因素：

- 触发时机改变。
- 被 reset 用户改变。
- reset 方向改变。

为了隔离本文贡献，reset 朝向沿用原有策略。本文只研究基于恢复余量的主动 reset 策略是否能改善局部恢复代价分量；具体选择哪一名用户是该策略的实现环节，用于近似分量指标改善目标。

因此，论文中不应把方向选择写成贡献。

## 9. 方法定义

本文方法可以定义为两步。

第一步，局部主动干预判定：

```text
Trigger(i,j) = 1
if 0 < M(i,j,H) ≤ θ(i,j)
and M has decreased in at least k of recent w frames
and closing_speed(i,j) > v_min
```

推荐初始设置：

```text
w = 5 frames
k = 3 frames
v_min = 0.05 m/s
```

第二步，主动 reset 动作选择：

```text
choose reset_i or reset_j
by maximizing the worse-side predicted remaining distance
```

该动作选择规则不是本文的独立贡献。它只是把“改善局部恢复代价分量”落到有限动作集合 `{keep, reset_i, reset_j}` 上的一个简单近似：优先避免 pair 中较差一侧在 reset 后很快再次进入短距离恢复。

同时加入最小收益门槛：

```text
R_selected - R_keep ≥ δ
```

推荐初始值：

```text
δ = 0.20m
```

若不满足该条件，则拒绝主动 reset。这样可以避免主动 reset 只是额外打断。

## 10. 研究问题

RQ1：在被动用户间 reset 下，局部用户间冲突事件是否存在 worst-case recovery failure？

对应指标：

- `I_bilateral`
- `I_short_min_τ`
- `D_next_min`
- `D_next_mean`
- `N_interrupted`

RQ2：基于恢复余量趋势的主动 reset 是否能提高局部冲突中较差一侧用户的恢复下界？

对应比较：

- Baseline vs Active Reset。
- `N_interrupted` 是否下降。
- `I_bilateral` 是否下降。
- `I_short_min_τ` 是否下降。
- `D_next_min` 是否显著提高。
- total reset rows 是否没有明显增加。
- `D_next_mean` 是否仅小幅变化，作为辅助解释。

## 11. 实验设计

实验 A：问题存在性。

目标是证明 baseline 中确实存在局部高代价恢复，而不是只存在普通 reset。

应报告：

- baseline 下双边用户 reset 数量和比例。
- baseline 下 `D_next_min < 1m/2m/3m` 比例。
- baseline 下 `D_next_min` 分布和低分位数。
- baseline 下 `D_next_mean` 分布，作为对照。

实验 B：主动 reset 主效果。

目标是证明 Active Reset 改善局部恢复代价分量，尤其是提高局部冲突中较差一侧用户的恢复下界，而不是只改变全局 reset 数量。

应报告：

- `N_interrupted` 均值或分布。
- `I_bilateral` 数量和比例。
- `I_short_min_τ` 在 `τ=1m/2m/3m` 下的比例。
- `D_next_min` 均值、中位数、低分位数。
- `D_next_min < 1m/2m/3m` 比例。
- total reset rows。
- ordinary USER_RESET rows。
- PROACTIVE_USER_RESET rows。
- USER + PROACTIVE 总量。
- `D_next_mean` 均值或中位数，作为辅助指标。

实验 C：触发阈值敏感性。

目标是证明主动窗口不是任意调参。

建议比较：

- conservative：`T_lead=0.20s, θ_max=0.35m, δ=0.25m`
- default：`T_lead=0.30s, θ_max=0.50m, δ=0.20m`
- aggressive：`T_lead=0.45s, θ_max=0.70m, δ=0.15m`

应观察：

- proactive reset count 是否过高。
- total reset rows 是否上升。
- `I_short_min_τ` 是否下降。
- `D_next_min` 是否提高。

用户选择规则可作为补充工程消融，但不作为主研究问题。若写入论文，应只用于说明该实现不是随意选择用户，而不应把它包装成独立方法贡献。

## 12. 贡献表述

推荐贡献写法：

1. 本文将多人 RDW 中用户间局部冲突后的恢复结果形式化为 pair-level 分量指标，包括被打断用户数、双边 reset、较差一侧短距离恢复比例和较差一侧连续行走距离。

2. 本文提出一种基于恢复余量趋势的主动 reset 判定方法，在 `M>0` 但恢复余量持续下降时触发候选干预，以改善局部冲突中的 worst-case recovery，而不是最大化全局平均连续行走距离。

3. 本文通过多用户仿真实验验证该方法是否改善局部恢复代价分量，包括降低 `N_interrupted`、降低 `I_bilateral`、降低 `I_short_min_τ`、提高 `D_next_min`，并分析其在不同用户密度和阈值设置下的适用边界。

## 13. 最短论文主线

多人 RDW 中，一次用户间局部冲突的代价不只取决于是否避免了即时碰撞，还取决于冲突处理后有多少用户被打断，以及恢复最差的用户还能连续走多远。本文将该问题定义为局部恢复代价分量改善问题，并以 `D_next_min` 描述 pair 中较差一侧用户的恢复下界。我们用恢复余量 `M=d_min-d_safe` 描述冲突是否仍处于可主动干预窗口，并在 `M>0` 但持续下降时触发主动 reset。随后，方法在有限动作集合 `{keep, reset_i, reset_j}` 中选择预计能改善恢复代价分量的动作；具体用户选择规则是工程近似，不作为独立研究贡献。该方法不优化 reset 方向，而是隔离检验基于恢复余量的主动 reset 是否能够减少双边 reset、减少较差一侧短距离连续 reset，并提高局部冲突中的 worst-case recovery distance。
