# 面向局部用户间冲突恢复代价的主动重置仲裁方法

## 1. 研究对象

本文研究的对象不是泛泛的“冲突恶化”，而是多人重定向行走中一次用户间局部冲突事件的恢复结果。

一个局部用户间冲突事件定义为：

> 在连续时间窗口 `[t0, t1]` 内，用户 `i` 和用户 `j` 的真实物理状态满足接近条件，并且该 pair 可能触发用户间 reset 或影响后续 reset 分布。

该事件至少需要满足两个条件：

1. pair 处于邻近或潜在碰撞候选关系，例如处于相邻 partition/cell，或真实距离低于候选距离阈值。
2. pair 的相对运动具有接近趋势，例如 closing speed 大于阈值，或预测最小距离低于当前距离。

只用“距离近”定义冲突是不够的。两个用户距离近但正在分离，不一定需要干预。本文关注的是“接近趋势可能导致后续 reset”的 pair-level 事件。

## 2. 恢复结果

本文将一次局部用户间冲突事件后的恢复结果定义为：

> 从该冲突事件被处理或自然结束开始，到下一次相关 reset 或相关用户间事件发生之前，系统给用户留下的连续行走结果。

恢复结果不是主观体验评价，而是一组可观测量。本文使用以下变量描述恢复结果：

- `N_reset_user`：该局部事件引发的用户相关 reset 数量。
- `N_interrupted`：被该局部事件打断的用户数量。单侧 reset 为 1，双边 reset 为 2。
- `D_next`：事件结束后到下一次相关 reset/event 的连续行走距离。
- `I_short(τ)`：短距离恢复指示函数。若 `D_next < τ`，则 `I_short(τ)=1`，否则为 0。本文可取 `τ=1m, 2m, 3m`。
- `I_bilateral`：双边 reset 指示函数。若同一局部事件导致两名用户均发生 user reset，则为 1，否则为 0。

其中，`D_next` 和 `I_short(τ)` 是恢复连续性的主要代理指标；`N_interrupted` 和 `I_bilateral` 是打断范围的主要代理指标。

## 3. 恢复代价

为避免“高代价”成为模糊表述，本文将局部恢复代价定义为一个可计算函数。

对一次局部用户间冲突事件 `e`，其恢复代价可写为：

```text
C(e) = α · N_interrupted(e)
     + β · I_short_τ(e)
     + γ · max(0, τ - D_next(e)) / τ
```

其中：

- `N_interrupted(e)` 衡量该事件打断了多少用户。
- `I_short_τ(e)` 衡量该事件后是否出现短距离恢复。
- `max(0, τ - D_next(e)) / τ` 衡量短距离恢复的严重程度。
- `α, β, γ` 是权重，用于表达不同代价项的重要性。

如果不希望引入加权和，也可以报告三个分量指标，而不合成单一分数：

```text
Cost components = {N_interrupted, I_short_τ, D_next}
```

论文主文建议优先报告分量指标，因为它们更直观，也更不依赖权重选择。加权代价函数可作为方法目标或补充定义。

## 4. 低代价恢复与高代价恢复

在上述定义下，低代价恢复不是主观判断，而是满足以下特征的恢复结果：

- 只打断一名用户，或没有触发用户 reset。
- `D_next` 较长。
- `I_short_τ=0`。
- 未出现双边 user reset。

高代价恢复定义为满足以下任一条件的恢复结果：

- `N_interrupted = 2`，即一次 pair-level 冲突打断两名用户。
- `I_short_τ = 1`，即冲突后在短距离内再次 reset。
- `D_next` 位于低分位或小于阈值 `τ`。

因此，“高代价”在本文中等价于：

> 更多用户被打断，或冲突后连续行走距离不足。

该定义与 RDW 文献中常用的 reset count 和 distance between resets 一致，但评价单位从全局 episode 收缩到局部用户间冲突事件。

## 5. 冲突状态与恢复余量

为了决定是否主动干预，需要定义冲突事件在当前时刻是否仍有恢复余量。

设用户 `i` 和 `j` 在预测窗口 `H` 内的最小预测距离为：

```text
d_min(i,j,H)
```

设安全距离为：

```text
d_safe = r_i + r_j + b
```

其中 `r_i` 和 `r_j` 是用户安全半径，`b` 是安全缓冲。

恢复余量定义为：

```text
M(i,j,H) = d_min(i,j,H) - d_safe
```

解释：

- `M > 0`：预测窗口内仍未进入安全边界，pair 仍有恢复余量。
- `M = 0`：预测最小距离刚好达到安全边界。
- `M < 0`：预测窗口内将进入安全边界，说明被动安全风险已经较高。

因此，本文不应把主动 reset 触发在 `M < 0` 之后。若 `M < 0` 才触发，该方法更接近预测版被动 reset，而不是利用恢复余量的主动干预。

## 6. 主动干预窗口

本文的主动干预窗口定义为：

```text
0 < M(i,j,H) ≤ θ(i,j)
and ΔM < 0 over recent frames
and closing_speed(i,j) > v_min
```

其中：

```text
θ(i,j) = clamp(closing_speed(i,j) · T_lead + b_uncertain,
               θ_min,
               θ_max)
```

推荐初始值：

```text
T_lead = 0.30s
b_uncertain = 0.05m
θ_min = 0.15m
θ_max = 0.50m
```

含义：

- 当前仍有恢复余量，即 `M > 0`。
- 余量已经进入保守阈值区间，即 `M ≤ θ`。
- 余量正在下降，即最近若干帧内 `M` 持续减小。
- pair 仍在接近，而不是自然分离。

这一定义避免了两个极端：

- 过晚触发：等到 `M < 0` 才处理，已经接近被动安全 reset。
- 过早触发：只要预测有风险就 reset，容易打断本可自然恢复的冲突。

## 7. 优化目标

本文的优化目标不是“减少所有 reset”，也不是“找到最优 reset 方向”。本文的目标是：

> 在主动干预窗口内，从有限动作集合中选择一个动作，使局部冲突事件的预期恢复代价最小。

动作集合为：

```text
A = {keep, reset_i, reset_j}
```

其中：

- `keep` 表示不主动干预，继续由现有 RDW 和被动 reset 机制处理。
- `reset_i` 表示主动重置用户 `i`。
- `reset_j` 表示主动重置用户 `j`。

目标函数为：

```text
a* = argmin_a E[C(e) | state_t, a]
```

在实际实现中，完整估计 `E[C]` 可能较难。因此本文使用可计算代理目标：

```text
maximize  min(R_i(a), R_j(a))
```

其中 `R_i(a)` 和 `R_j(a)` 表示执行动作 `a` 后，pair 中两个用户各自预计还能获得的可连续行走距离。该目标对应局部 max-min 仲裁：

> 不追求某一名用户的最大收益，而是提高当前 pair 中较差一侧的恢复下界。

## 8. 为什么不是方向优化

reset 方向优化回答的是：

> 已经决定 reset 后，朝哪里 reset 更好？

本文回答的是：

> 是否应在被动 reset 前主动干预，以及应该 reset 哪一名用户？

这两个问题不同。若同时引入新的方向优化，实验收益将混合来自三个因素：

- 触发时机改变。
- 被 reset 用户改变。
- reset 方向改变。

为了隔离本文贡献，reset 朝向沿用原有策略。本文只研究主动干预窗口和单侧用户仲裁是否能降低局部恢复代价。

因此，论文中不应把方向选择写成贡献。

## 9. 方法定义

本文方法可以定义为两步。

第一步，局部主动干预判定：

```text
Trigger(i,j) = 1
if 0 < M(i,j,H) ≤ θ(i,j)
and M has decreased in at least k of recent w frames
and closing_speed(i,j) > v_min
```

推荐初始设置：

```text
w = 5 frames
k = 3 frames
v_min = 0.05 m/s
```

第二步，单侧 reset 仲裁：

```text
choose reset_i or reset_j
by maximizing the worse-side predicted remaining distance
```

同时加入最小收益门槛：

```text
R_selected - R_keep ≥ δ
```

推荐初始值：

```text
δ = 0.20m
```

若不满足该条件，则拒绝主动 reset。这样可以避免主动 reset 只是额外打断。

## 10. 研究问题

RQ1：在被动用户间 reset 下，局部用户间冲突事件是否存在较高恢复代价？

对应指标：

- `I_bilateral`
- `I_short_τ`
- `D_next`
- `N_interrupted`

RQ2：基于恢复余量趋势的主动 reset 是否能降低局部恢复代价？

对应比较：

- Baseline vs Active Reset。
- `N_interrupted` 是否下降。
- `I_short_τ` 是否下降。
- `D_next` 是否提高。
- total reset rows 是否没有明显增加。

RQ3：局部 max-min 仲裁是否优于简单选人策略？

对应消融：

- Max-min arbitration。
- Closest-user selection。
- Highest-risk-user selection。
- Random selection。
- Fixed-side selection。

## 11. 实验设计

实验 A：问题存在性。

目标是证明 baseline 中确实存在局部高代价恢复，而不是只存在普通 reset。

应报告：

- baseline 下双边用户 reset 数量和比例。
- baseline 下 `D_next < 1m/2m/3m` 比例。
- baseline 下 `D_next` 分布和低分位数。

实验 B：主动 reset 主效果。

目标是证明 Active Reset 降低局部恢复代价。

应报告：

- total reset rows。
- ordinary USER_RESET rows。
- PROACTIVE_USER_RESET rows。
- USER + PROACTIVE 总量。
- `D_next` 均值、中位数、低分位数。
- `D_next < 1m/2m/3m` 比例。

实验 C：仲裁消融。

目标是证明收益不是由“任意提前 reset”产生，而是与用户选择有关。

应比较：

- max-min。
- 最近用户。
- 最高风险用户。
- 随机用户。
- 固定用户。

实验 D：触发阈值敏感性。

目标是证明主动窗口不是任意调参。

建议比较：

- conservative：`T_lead=0.20s, θ_max=0.35m, δ=0.25m`
- default：`T_lead=0.30s, θ_max=0.50m, δ=0.20m`
- aggressive：`T_lead=0.45s, θ_max=0.70m, δ=0.15m`

应观察：

- proactive reset count 是否过高。
- total reset rows 是否上升。
- `I_short_τ` 是否下降。
- `D_next` 是否提高。

## 12. 结果解释原则

如果 Active Reset 使 `D_next` 提高，同时 total reset rows 没有增加，可解释为：

> 主动 reset 替代了部分较高代价的被动恢复。

如果 Active Reset 使 `D_next` 提高，但 total reset rows 明显增加，应谨慎解释为：

> 主动 reset 增加了额外打断，收益需要通过代价函数权重进一步判断。

如果 3 用户场景收益不显著，但 4/5/6 用户显著，可解释为：

> 方法更适用于中高冲突密度场景；低冲突场景中自然恢复概率较高，主动干预空间较小。

不能写：

- “显著改善沉浸感”，除非有主观实验。
- “降低总代价”，除非定义并报告总代价函数。
- “解决用户间碰撞”，因为本文只处理局部恢复代价。

## 13. 贡献表述

推荐贡献写法：

1. 本文将多人 RDW 中用户间局部冲突后的恢复结果形式化为可观测指标，包括被打断用户数、短距离恢复比例和冲突后连续行走距离。

2. 本文提出一种基于恢复余量趋势的主动 reset 判定方法，在 `M>0` 但恢复余量持续下降时触发候选干预，以避免退化为预测版被动 reset。

3. 本文提出局部 max-min 单侧仲裁策略，在不改变原有 reset 方向策略的前提下，选择能够改善 pair 较差恢复结果的一侧用户执行 reset。

4. 本文通过多用户仿真实验验证该方法是否降低局部恢复代价，并分析不同用户密度和阈值设置下的适用边界。

## 14. 最短论文主线

多人 RDW 中，一次用户间局部冲突的代价不只取决于是否避免了即时碰撞，还取决于冲突处理后有多少用户被打断，以及用户能连续走多远。本文将该问题定义为局部恢复代价最小化问题。我们用恢复余量 `M=d_min-d_safe` 描述冲突是否仍处于可主动干预窗口，并在 `M>0` 但持续下降时触发单侧主动 reset。随后，方法通过局部 max-min 仲裁选择 reset 用户，以提高当前 pair 中较差一侧的恢复下界。该方法不优化 reset 方向，而是隔离检验触发时机和用户选择是否能够降低双边 reset 与短距离连续 reset 等局部恢复代价。
